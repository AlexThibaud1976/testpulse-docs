TestPulse builds reports and analyses **in your browser**, using Azure DevOps reads. Calculating a score does not modify your test results. Some features do create or change objects, and the extension automatically saves working data.

Distinguish **Azure DevOps business data** — plans, suites, points, work items and attachments — from **TestPulse data** stored in Azure DevOps Extension Data. “Read-only” for the former does not mean “no saves” for the latter.

## Action matrix

| Feature or action | Reading and processing | What is saved or sent | Trigger |
| --- | --- | --- | --- |
| Generate a report | Plans, suites, cases, points, results, requirements and bugs; calculations in the browser. | Report snapshot in personal Extension Data history. No test result is modified. | **Generate**, followed by automatic saving. |
| View Test coverage, coverage or drift | Work items, links and results needed for the analysis. | Presentation or scope preferences depending on the screen; no corrections to requirements or results. | Opening, analysing or choosing a filter. |
| Open the Cockpit | Test points and campaign data. | Tracking snapshots in Extension Data; local target and settings when entered. The plan's date and results are unchanged. | Loading the Cockpit and changing settings. |
| Organise the Repository | Existing test cases and their locations. | Folders, case references and organisation state in project-level Extension Data; caches and presentation preferences. | Creating, filing, moving, bootstrapping; caching during reads. |
| Create from Coverage Builder | Requirements, links and plan preview. | New plan and requirement-based suites in Azure DevOps. | Confirming **Create plan in ADO**. |
| Generate from Repository | Selected folders and target preview. | New plan and suites, or cases added to an existing plan/suite depending on the target. Cases are not copied. | Confirming the preview. |
| Bulk reassign | Points in scope and impact preview. | Testers or configurations for the selected points. | Explicit confirmation to apply. |
| Run an Explore session | Host work item and session information. | Session and index in Extension Data, with autosave; captures and files uploaded as Azure DevOps attachments. | Starting, taking notes, capturing or dropping a file. |
| Create a bug or test case from Explore | Selected session entries. | New work item, relations and selected attachments. | Creation action in the dedicated panel. |
| Close an Explore session | Session and selected entries. | Tracking Task with report, links and attachments; that Task's state if requested. The session is saved as closed. | Confirmed closure dialog. |
| Record a promotion decision | Environment, transition and decision. | Decision in the session; when host reporting is enabled, a tag and comment on the host work item. Its state and assignee are unchanged. | Decision recorded at closure. |
| Import XML | File parsed in the browser; Azure DevOps reads for the plan and test-case mapping. | **[AUTO]** report in Extension Data history. No run or result is published to Test Plans. | **Import** after preview. |
| Share, annotate or approve a report | Saved snapshot. | Project-shared copy, notes and status transitions in Extension Data. | Corresponding history action. |
| Export | Report, analysis or session; some images are read again from Azure DevOps. | File downloaded to your device. | Chosen format's button. |
| Test a webhook or notify | Message built in the browser. | Sample message or title, environment and KPIs sent to the configured Teams/Slack URL. | **Test** or **Notify**. |

## Writes to existing objects

[Generation from Repository](/en/test-repository/generate-a-plan) can add cases to an existing shared structure. [Bulk reassignment](/en/reports/bulk-reassignment) changes testers or configurations. A [promotion decision](/en/exploratory/promotion-decision) can add a tag and comment to the host work item. These actions have different effects: check the target and preview of the action you use.

<Warning>
Bulk reassignment has no undo command. Changing a **configuration** can cause Azure DevOps to recreate a point and lose its associated result. The preview lets you exclude points that were already run. Export the previous state as CSV before applying if you need a record.
</Warning>

## Automatic saving and sharing

History, Cockpit snapshots and Explore sessions explain why TestPulse can write to **Extension Data** without asking you to confirm every save. This storage belongs to Azure DevOps; it does not create a TestPulse backend. Its scope varies: personal history per user, shared reports and several settings at project level. See [Privacy and data](/en/security/privacy).

There is no TestPulse service generating reports while your browser is closed: [scheduled reports](/en/collaboration/notifications-and-scheduling) are reminders displayed when you open the extension.

## Data leaving Azure DevOps

**No TestPulse backend receives your reports.** That does not mean data cannot leave Azure DevOps: exports become local files, and **Test** or **Notify** sends a message to your chosen webhook. Any subsequent sharing of those files and the channel's recipients depend on your choices.
