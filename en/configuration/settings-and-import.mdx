## The Settings screen

Most settings persist **per user** via Azure DevOps Extension Data; a few (a shared scale profile, project-shared reports, the environment stages, the Cockpit's load per tester, the bug source) are **project-scoped** so a whole team sees the same thing.

| Setting | What it controls |
| --- | --- |
| **Header & footer label** | Replaces "TestPulse" in the header, footer and file name — see [Cover page](/en/reports/cover-page). |
| **Field configuration** | Per-field regex, soft length and the cover-page toggle — see [Generate a report](/en/reports/generate-a-report). |
| **Visible export buttons** | Which export buttons appear — see [Show or hide export buttons](/en/exports/button-visibility). |
| **PDF section order** | Reorder and toggle PDF sections — see [Export formats](/en/exports/formats). |
| **Notifications** | Teams / Slack webhooks — see [Notifications](/en/collaboration/notifications-and-scheduling). |
| **Scheduled reports** | Recurring report reminders — see [Scheduled reports](/en/collaboration/notifications-and-scheduling). |
| **Quality scale & GO/NO-GO override** | Scale profile and the opt-in decision override — see [Quality Gate](/en/quality/quality-gate). |
| **Bug source** | Where the bugs of a report come from — the plan runs (default) or the test case and User Story links; a project setting, stamped with who changed it and when — see [Bugs of a report](/en/reports/campaign-bugs). |
| **Assess coverage depth** | The opt-in depth analysis — see [Coverage depth](/en/quality/coverage-depth). |
| **Environment stages** | The project ladder (TEST → QUAL → PROD by default) and the switch for reporting on the host work item — see [Promotion decision](/en/exploratory/promotion-decision). |
| **Cockpit** | *Show load per tester* — a project setting, on by default; when off, the card disappears for everyone and testers are not read — see [Execution Cockpit](/en/cockpit/execution-cockpit). |

## Import external results

Open **Import → Automated XML results** and drag-and-drop (or pick) an `.xml` file produced by **Cypress, Playwright, Surefire / Maven, NUnit 3 or xUnit 2**. The format is auto-detected from the root tag. Parsed results are previewed (name, outcome, duration, mapped) and **auto-mapped to Azure DevOps test cases by name** (case-insensitive contains); unmapped rows get a manual dropdown. Pick the target plan and click **Import** — a report is saved to History with an **[AUTO]** badge.

<Frame caption="The import drop zone: JUnit, Cypress, Playwright, Surefire, NUnit 3 and xUnit 2 XML files.">
  <img src="/images/en/import-dropzone.png" alt="Results import drop zone listing the supported XML formats" />
</Frame>

<Note>The XML is parsed **in the browser**. Loading the plan and cases for mapping reads Azure DevOps; saving the report writes to Extension Data. XML import **does not publish any run or test result to Azure Test Plans**.</Note>

## Import CSV test cases

The new **Import → CSV test cases** choice prepares cases, their steps and their placement in a plan. It can reuse existing **static** suites or create missing levels, with a preview before confirmation. An existing **ID** reuses a case without replacing its steps. This workflow **writes objects and memberships to Azure DevOps**; its recovery journal stays local to the browser.

This workflow is available from **2.74.0**. Since **2.74.2**, search plans by name or ID and static suites by name, full path or ID. For new cases in an existing plan, review the area and optional iteration proposed from that plan; populated CSV fields take priority. Suite paths and work-item area paths are distinct, with separate permissions. Follow the [complete CSV tutorial](/en/tutorials/import-csv-test-cases) for the file format, a mixed-mapping example, TF237111 troubleshooting and recovery after an interruption. The XML workflow above remains dedicated to automated results and **AUTO** reports.

## Consolidated multi-plan reports

Toggle **Multi-plan mode** in the plan selector to pick several plans. A single **Generate** produces one consolidated report: **global metrics** plus a **per-plan breakdown** (each plan's total, pass rate, execution rate and counts) and a **Plan** column in the results table — on screen and in every export. Overlapping test cases are de-duplicated (most recent result wins); a note explains why per-plan totals may exceed the consolidated total. A non-blocking warning appears beyond three plans; single-plan behaviour is unchanged.
