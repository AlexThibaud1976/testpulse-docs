## L'écran Paramètres

La plupart des paramètres sont mémorisés **par utilisateur** via Azure DevOps Extension Data ; quelques-uns (un barème partagé, les rapports partagés au projet, les environnements, la charge par testeur du Cockpit, la source des bugs) sont **au niveau projet** pour que toute une équipe voie la même chose.

  <img src="/images/fr/settings-branding.png" alt="Écran Paramètres de TestPulse, section Marque et page de garde" />
</Frame>

| Paramètre | Ce qu'il contrôle |
| --- | --- |
| **Libellé d'en-tête & pied de page** | Remplace « TestPulse » dans l'en-tête, le pied de page et le nom de fichier — voir [Page de garde](/fr/reports/cover-page). |
| **Configuration des champs** | Regex, longueur douce et toggle page de garde par champ — voir [Générer un rapport](/fr/reports/generate-a-report). |
| **Boutons d'export visibles** | Quels boutons d'export apparaissent — voir [Afficher ou masquer les boutons d'export](/fr/exports/button-visibility). |
| **Ordre des sections PDF** | Réordonner et activer les sections PDF — voir [Formats d'export](/fr/exports/formats). |
| **Notifications** | Webhooks Teams / Slack — voir [Notifications](/fr/collaboration/notifications-and-scheduling). |
| **Rapports programmés** | Rappels de rapports récurrents — voir [Rapports planifiés](/fr/collaboration/notifications-and-scheduling). |
| **Barème qualité & override GO/NO-GO** | Profil de barème et override de décision opt-in — voir [Quality Gate](/fr/quality/quality-gate). |
| **Source des bugs** | D'où viennent les bugs d'un rapport — les exécutions du plan (par défaut) ou les liens des cas de test et des User Stories ; réglage projet, estampillé de qui l'a modifié et quand — voir [Les bugs du rapport](/fr/reports/campaign-bugs). |
| **Évaluer la profondeur de couverture** | L'analyse de profondeur opt-in — voir [Profondeur de couverture](/fr/quality/coverage-depth). |
| **Environnements** | L'échelle du projet (TEST → QUAL → PROD par défaut) et l'interrupteur du report sur la fiche hôte — voir [Décision de passage](/fr/exploratory/promotion-decision). |
| **Cockpit** | *Afficher la charge par testeur* — réglage projet, activé par défaut ; désactivé, la carte disparaît pour tous et les testeurs ne sont pas lus — voir [Cockpit d'exécution](/fr/cockpit/execution-cockpit). |

## Importer des résultats externes

Ouvrez **Import → Résultats automatisés XML** et glissez-déposez (ou choisissez) un fichier `.xml` produit par **Cypress, Playwright, Surefire / Maven, NUnit 3 ou xUnit 2**. Le format est détecté automatiquement depuis le tag racine. Les résultats analysés sont prévisualisés (nom, résultat, durée, mappé) et **auto-mappés aux cas de test Azure DevOps par nom** (contains insensible à la casse) ; les lignes non mappées reçoivent une liste manuelle. Choisissez le plan cible et cliquez sur **Importer** — un rapport est sauvegardé dans l'Historique avec un badge **[AUTO]**.

<Frame caption="La zone de dépôt d'import : fichiers XML JUnit, Cypress, Playwright, Surefire, NUnit 3 et xUnit 2.">
  <img src="/images/fr/import-dropzone.png" alt="Zone de dépôt d'import des résultats listant les formats XML pris en charge" />
</Frame>

<Note>Le parsing du XML se fait **dans le navigateur**. Le chargement du plan et des cas pour le mapping lit Azure DevOps ; la sauvegarde du rapport écrit dans Extension Data. L'import XML **ne publie aucun run ni résultat de test dans Azure Test Plans**.</Note>

## Importer des cas de test CSV

Le nouveau choix **Import → Cas de test CSV** prépare des cas, leurs étapes et leur classement dans un plan. Il permet de réutiliser des suites **statiques** existantes ou de créer les niveaux manquants, avec un aperçu avant confirmation. Un **ID** existant réutilise le cas sans en remplacer les étapes. Ce parcours **écrit des objets et rattachements dans Azure DevOps** ; son journal de reprise reste local au navigateur.

Ce parcours est disponible à partir de **2.74.0**. Depuis **2.74.2**, recherchez les plans par nom ou ID et les suites statiques par nom, chemin complet ou ID. Pour les nouveaux cas dans un plan existant, contrôlez la zone et l'itération facultative proposées depuis ce plan ; les champs renseignés dans le CSV sont prioritaires. Chemins de suites et zones des work items sont distincts, avec leurs propres permissions. Suivez le [tutoriel CSV complet](/fr/tutorials/import-csv-test-cases) pour le format du fichier, un exemple de correspondance mixte, le dépannage TF237111 et la conduite à tenir après une interruption. L'import XML décrit ci-dessus reste destiné aux résultats automatisés et aux rapports **AUTO**.

## Rapports consolidés multi-plans

Activez le **Mode multi-plans** dans le sélecteur pour cocher plusieurs plans. Un unique **Générer** produit un rapport consolidé : **métriques globales** plus un **détail par plan** (total, taux de réussite, taux d'exécution et compteurs de chaque plan) et une colonne **Plan** dans la table des résultats — à l'écran et dans chaque export. Les cas de test en recouvrement sont dédoublonnés (le résultat le plus récent gagne) ; une note explique pourquoi la somme des totaux par plan peut dépasser le consolidé. Une alerte non bloquante apparaît au-delà de trois plans ; le comportement single-plan est inchangé.
