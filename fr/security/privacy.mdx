TestPulse construit les rapports **dans votre navigateur**. Il n'a pas de backend TestPulse qui reçoit ou analyse vos données de projet. Les données circulent néanmoins entre le navigateur et Azure DevOps ; vos actions d'export ou de notification peuvent aussi les faire sortir de cet environnement.

## Où vivent vos données

| Données | Stockage et visibilité |
| --- | --- |
| **Rapports et historique personnel** | Azure DevOps **Extension Data**, par utilisateur à l'échelle de l'organisation. |
| **Rapports partagés** | Copie du rapport dans Extension Data au niveau projet, quand vous choisissez **Partager avec le projet**. |
| **Préférences et réglages** | Extension Data, avec portée utilisateur ou projet selon le réglage ; certains choix purement visuels sont conservés dans le navigateur. |
| **Repository et snapshots Cockpit** | Données propres à l'extension dans Azure DevOps ; l'organisation du référentiel et les données partagées de suivi ne sont pas des modifications des résultats de test. |
| **Sessions exploratoires** | Documents et index dans Extension Data au niveau projet ; sauvegarde automatique pendant la session. |
| **Captures et fichiers Explore** | Pièces jointes téléversées dans Azure DevOps, puis liées aux work items selon vos actions de création ou de clôture. |
| **Images d'un rapport** | Chargées depuis Azure DevOps et mises en cache en mémoire ; retirées de l'instantané d'historique pour respecter son quota, puis relues si nécessaire. |
| **Exports** | Fichiers téléchargés sur votre appareil. Ils suivent ensuite les règles de stockage et de partage de cet appareil et de vos destinataires. |
| **Notifications** | Message envoyé depuis le navigateur à l'URL de webhook configurée, quand vous choisissez **Tester** ou **Notifier**. |

<Warning>
Le scope projet des sessions n'est pas une frontière de confidentialité entre équipes : les documents de session sont partagés au niveau projet. Le filtre **Testeur** du hub sert à retrouver des sessions ; il ne constitue pas un contrôle d'accès. La reprise d'une session active réservée à son auteur ne rend pas son contenu privé. Évitez d'y placer des informations qui ne doivent pas être accessibles aux membres du projet.
</Warning>

## Ce qui sort par export ou notification

Un PDF, un document Word, un classeur Excel, un HTML ou une présentation PowerPoint devient un **fichier local**. TestPulse ne contrôle plus sa diffusion une fois que vous le partagez.

Pour Teams ou Slack, le message de rapport contient son **titre**, son **environnement**, son **taux de réussite**, son **taux d'exécution** et son **nombre de bugs**. Le bouton **Tester** envoie un message d'exemple. Le destinataire est l'URL enregistrée dans vos réglages ; le contenu n'est pas envoyé à un serveur TestPulse. Voir [Notifications](/fr/collaboration/notifications-and-scheduling).

## Télémétrie et services externes

TestPulse n'intègre pas de backend d'analytics pour collecter vos rapports. Les accès aux données du produit passent par Azure DevOps et les notifications que vous déclenchez utilisent vos webhooks. Cette description concerne TestPulse ; elle ne remplace pas les politiques propres à Azure DevOps, Teams, Slack ou à votre navigateur.

## Azure DevOps Server

Les données Azure DevOps sont lues et enregistrées contre votre serveur. Les notifications restent des requêtes sortantes du navigateur : selon la politique réseau et CORS, elles peuvent être refusées. TestPulse propose alors le payload à copier pour un traitement manuel. Les exports locaux restent possibles.
