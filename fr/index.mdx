## Apprendre en pratiquant

Les ateliers utilisent une même boutique fictive. Vous pouvez [préparer le jeu de démonstration](/fr/tutorials/demo-project) dans un projet dédié ou suivre les étapes avec un petit plan de test que vous connaissez. Le tutoriel CSV fournit ses propres fichiers pour apprendre le classement dans les suites.

| Atelier | Votre résultat à la fin |
|---|---|
| [Mon premier rapport](/fr/tutorials/first-report) | Un rapport relu, un PDF et un rapport retrouvé dans l’historique. |
| [Comprendre un NO-GO](/fr/tutorials/understand-no-go) | Une explication du verdict appuyée sur le périmètre, les règles et les preuves. |
| [Une session exploratoire complète](/fr/tutorials/exploratory-session) | Une session documentée, un bug traçable et un compte rendu partageable. |
| [Importer des cas CSV](/fr/tutorials/import-csv-test-cases) | Des tests placés dans les bonnes suites statiques, un aperçu contrôlé et un bilan d'import. |

## Une aide directement dans Azure DevOps

Dans **TestPulse → Documentation**, onze guides courts vous accompagnent sur le premier rapport, le NO-GO, Explore, Repository, Couverture, Cockpit, la dérive des exigences, l'import de résultats XML, l'import de cas CSV, l'historique et le partage, et la réaffectation. Chaque guide réunit prérequis, étapes, résultats attendus et dépannage. La référence détaillée reste accessible.

La recherche embarquée accepte plusieurs mots, avec ou sans accents, et privilégie les titres correspondants. Les raccourcis et résultats sont utilisables au clavier. Cette aide complète les **trois ateliers illustrés en ligne** et le tutoriel CSV ci-dessus. Voir les [nouveautés de la version 2.74.0](/fr/changelog).

## Des résultats à interpréter

Un grade et un verdict résument des règles appliquées aux données disponibles. Ils ne remplacent pas la décision de l’équipe : vérifiez le périmètre, la fraîcheur des résultats et les informations manquantes. TestPulse **ne lance pas vos tests**.

<Note>
  TestPulse s’exécute dans votre navigateur, sans backend TestPulse. Selon les actions utilisées, il lit ou écrit dans Azure DevOps, sauvegarde des informations dans Extension Data, produit des fichiers locaux ou envoie une notification au webhook configuré. Consultez la [matrice des actions](/fr/concepts/read-only) et les [règles de confidentialité](/fr/security/privacy).
</Note>

La documentation couvre Azure DevOps Services et les particularités de Server présentées dans le [guide d’installation](/fr/getting-started/installation). Les captures des ateliers sont réalisées sur Services ; votre présentation peut varier selon la version, les droits et la configuration.
